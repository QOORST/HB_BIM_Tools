## 下一步唯讀盤點能力

在 Revit 有效 API 情境讀取並輸出 JSON，不開 Transaction：

1. 樣板：UniqueId、名稱、ViewType、控制參數、比例控制狀態；對候選來源驗證樣板適用性。
2. 圖框：已載入 FamilySymbol 的族名／型別名／UniqueId；既有圖紙上的實例與紙張尺寸。型別無實例時尺寸可能未知，保留待確認，不任意啟用型別。
3. 圖紙：圖號、圖名、圖框實例、已配置視圖與位置。
4. 視圖：UniqueId、ViewTemplateId、比例、裁剪、樓層、是否可複製與是否已放圖紙。
5. 讀取公司規則或由使用者指定一張範例圖；不由圖名猜測唯一規則。

## 第一階段交付：單層可重跑出圖流程

來源與既有樣板／圖框選擇 → 前置檢查 → 成果預覽 → 建立或更新專用視圖 → 標註 → 放置圖紙 → 檢核 → PDF。

工作台分為圖面清單、問題清單、生成設定及執行結果。非模態，所有 Revit 模型操作透過 ExternalEvent，請求綁定 Document 並防止重複執行。

### 模組與共用

| 模組 | 既有可用能力 | 新增工作 |
| --- | --- | --- |
| 出圖盤點 | BIM 標準檢查、MCP 部分視圖讀取 | 完整樣板／圖框／圖紙唯讀快照 |
| 視圖準備 | 使用者既有樣板 | 複製策略、適用性、命名衝突、裁剪與比例檢查 |
| 線條檢查 | 模型與接合相關幾何能力 | 梁／板分割疑點定位；不把接合直接視為出圖驗收 |
| 標註 | 自動尺寸、軸線標頭、標籤對齊 | 抽出共用服務與設定快照，避免模擬點擊既有視窗 |
| 圖紙 | 尚未確認完整現成服務 | 圖框、圖號、Viewport 配置及超框檢查 |
| 輸出 | 明細表匯出不能直接代替圖紙輸出 | PDF 指定圖紙、檔名、成功／失敗清單 |

## 必守規則

- 使用既有樣板；不修改公司樣板定義。樣板控制的比例／顯示參數不強行覆寫，需明示衝突。
- 第一期線條整理只做疑點清單、定位及使用者確認；不自動隱藏所有樓板線，不承諾尚未驗證的逐邊 API。
- 外緣、洞口、高差列為保護對象；不因為圖面清理而自動修改全模型接合。
- 每個生成成果記錄來源 UniqueId、圖面用途、工具識別與版本；重跑先查記錄，名稱相同但非工具建立的成果不覆寫。
- 僅更新工具擁有的尺寸、標籤及配置；使用者修改的成果需檢出衝突，不直接刪除重建。
- 每張圖獨立交易群組，錯誤回復該張；PDF 為交易外輸出，區分「圖紙建立成功／輸出失敗」，不可宣稱檔案會隨 Revit Undo 回復。
- 既有視圖／圖紙與工具生成視圖／圖紙明確區別；不以名稱推定所有權。

## 驗收條件

- 使用者指定樓層、樣板、圖框與命名規則後，先產生可檢視的生成計畫。
- 第一輪產出一張專用視圖、一張圖紙、一份 PDF 及檢核報告；必要資訊缺漏時停止該步並列出原因。
- 相同設定重跑不增加重複視圖、圖紙、尺寸；修改來源後可辨識待更新項目。
- 原視圖與樣板不被意外修改；洞口／高差等必要圖示人工驗收。
- 中途取消、文件切換、圖號重複、圖框缺漏、樣板不適用、PDF 路徑不可寫均有明確結果。
- 此階段不包含全棟自動排版、全自動消除板縫或所有圖種生成。
