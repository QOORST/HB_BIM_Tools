# 套管安全性第一階段

範圍：建立／更新標註保護、管理視窗文件隔離、交易成功統計。未包含差異預覽、CAD 自動辨識或標註重建。

## 已修改
- WPF 與新版設定入口共用 ExecuteCreate，交易群組提交後檢查既有套管身分與尺寸／標籤參考。
- 建立流程不再自動刪除失配舊套管；保留並提示。更新拒絕換型與非唯一配對。
- 成功計數在子交易提交後累加。RegenerationFailedException 中止外層交易。
- 管理更新共用 SleeveAnnotationGuard；手動刪除仍為使用者明確操作，不包含在自動更新保護範圍。
- 關窗只標記，Idling/API 回呼釋放事件；模型切換、關閉取消待執行操作；禁止要求互相覆蓋。

## 驗證
- 2024／2026 編譯通過。
- 32 項模擬斷言通過：標註不變、構件刪除／身分變更、尺寸參考失效、標籤孤立／目標變更、關窗、切換模型、無效文件、正常執行、取消與重複要求。
- 測試使用實際標註保護原始碼，以及從實際管理檔抽出的事件處理器；模擬 API 不等於原生 Revit 驗收。

## 待實機驗收
1. 2024／2026 各用模型副本，既有套管含尺寸及標籤，移動管線後由兩種入口更新。
2. 失配舊套管必須保留；換型／多重配對不移動原套管；標註參考失效時整批回復。
3. 更新後僅更新數量大於零時，不得被外部指令回報取消。
4. 管理清單開啟時切換、關閉文件，待執行刪除／更新不得寫入其他文件。
5. 關窗重開、按下要求後關窗、拒絕外部事件及關閉 Revit 不得出現 API context 例外。
6. 建立部分失敗及提交回復時，完成數量須與實際保留套管一致。

建立入口保守保護模型內已辨識套管，會掃描尺寸與標籤；大量圖面效能仍需驗收。不承諾保留所有非尺寸／標籤類型的相依關係。
