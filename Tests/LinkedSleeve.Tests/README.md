# 連結管線來源驗證

執行：`dotnet run --project Tests/LinkedSleeve.Tests/LinkedSleeve.Tests.csproj -c Release`。

直接編譯正式 `SleevePipeSource.cs`，以 API 替身驗證來源識別、模型座標轉換呼叫及紀錄讀寫。包含同 ID 跨文件、同檔多連結實例、旋轉與平移、鏡射、重複選取、連結卸載／重載／刪除／替換，以及來源刪除後 ID 重用。

## 使用流程

1. 自動套管 → 連結管線來源。
2. 選取已載入直接連結內的管線、風管、電管或電纜線架。
3. 指定目前模型的約束樓層，選擇要偵測的本機／連結穿越構件及套管族型。
4. 確認建立；套管、編號、數量表與發圖成果均屬目前模型。
5. 來源或連結位置變更並重新載入後，在套管管理重新檢查 → 更新 → 檢視預覽 → 確認。

此模式不寫入連結文件、不複製來源管線、不自動刪除來源遺失的套管，也不自動猜測跨文件樓層。第一版只支援直接連結，不遍歷巢狀連結。更新保留既有套管身分、標註參考與約束樓層；無法唯一配對或需要換型時保留原件並提示。

## Revit 原生驗收待辦

離線替身不能驗證 Revit 的實體幾何、選取或交易。2022／2024 各自驗收：

- 本機管線原流程與既有舊套管更新維持正常。
- 連結管線穿本機牆、梁、樓板；連結管線穿另一連結內的構件。
- 同一機電檔兩個實例位於不同位置，套管不互相配對；重複執行不重複建立。
- 來源及宿主連結具平移、旋轉、高程差或鏡射時，穿越點和軸向符合構件。
- 管線移動或來源／宿主連結移動後，更新預覽與實際位置一致；保留原元素 ID、編號、樓層和標註。
- 來源連結卸載、刪除或替換時提示正確，不配到本機同 ID 或另一個連結實例；重載後可再檢查。
- 取消選取、取消設定、取消更新或交易失敗均不留下半套管。
- 數量表仍計算本機生成套管；連結來源問題呈現在管理與待確認項目。

本次實作不等同部署；Revit 2025／2026 尚未執行年版原生驗證。
